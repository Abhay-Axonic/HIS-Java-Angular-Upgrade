# Audit: Silent Exception-Swallow Patterns — legacy/RabbitMQ module

*Read-only audit, 2026-07-06. Same method as `docs/AUDIT_Billing_exceptions.md`, `docs/AUDIT_Global_exceptions.md`, `docs/AUDIT_ADT_exceptions.md`, `docs/AUDIT_BloodBank_exceptions.md`, `docs/AUDIT_CSSDMaster_exceptions.md`, `docs/AUDIT_Pharmacy_exceptions.md`, `docs/AUDIT_DietAndKitchen_exceptions.md`, and `docs/AUDIT_OTIMS_exceptions.md`; scope here is the RabbitMQ module — a message-queue integration layer intended to relay HIS/EMR/OTIMS master-data messages to/from the Hospital Information System via RabbitMQ.*

**Scope:** every `.java` file under `legacy/RabbitMQ` (4 files, all under `src/main/java`, no `src/test/java` directory exists) — `com/param/rabbitmq/controller/RabbitMQController.java`, `com/param/rabbitmq/controller/RabbitMQConsumerController.java`, `com/param/rabbitmq/service/HisService/IHisService.java`, `com/param/rabbitmq/service/HisService/HisService.java`. Only **1 catch block is structurally live**; a raw grep finds 5 `catch(` occurrences total, but 4 of them sit inside two files that are entirely wrapped in a single `/* ... */` block comment (see Method).

**Method:** read-only, full manual read of all 4 files given the tiny size of this module (no sampling needed), cross-checked against a raw `catch\s*(` grep (5 raw occurrences across the 4 files: 3 in `RabbitMQController.java`, 1 in `RabbitMQConsumerController.java`, 1 in `HisService.java`; `IHisService.java` is a pure interface with 0). The 4-occurrence gap between the raw count and the 1 structurally-live catch was verified two ways: (1) both `RabbitMQController.java` and `RabbitMQConsumerController.java` contain exactly one `/*` and one `*/` each (checked with `grep -c`), spanning from line 1 (`/*package com.param.rabbitmq.controller;`) to the file's final line (`*/`) — i.e. the entire file, not just a method, is commented out; (2) `legacy/RabbitMQ/target/classes/com/param/rabbitmq/` contains compiled `.class` files only for `HisService` and `IHisService` — no `.class` file exists anywhere for either controller, confirming the Maven build never compiles them, which is consistent with (and independently corroborates) them being dead/commented-out source. This is the same "commented-out scaffolding" artifact noted in the Billing/Pharmacy/DietAndKitchen/OTIMS audits, but at whole-file granularity here rather than a single dead method inside an otherwise-live file. No file under `legacy/` was modified.

**Definition used (per task, identical to every prior audit in this series):** a finding is any catch block that is (a) empty, (b) returns `null`/a generic hardcoded error with no logging of the real cause, or (c) neither logs (via a real logger call) nor rethrows. Catch blocks that call a logger (`logger.error(...)`, etc.) or that `throw`/rethrow are excluded as non-findings.

## Methodology caveats (read before acting on this list)

- **Two of the four files are entirely dead code, not just partially commented scaffolding.** `RabbitMQController.java` and `RabbitMQConsumerController.java` are each a single `/* ... */` block spanning the whole file (verified: exactly one `/*` and one `*/` per file, at the very first and very last line respectively), and neither has a corresponding `.class` file under `legacy/RabbitMQ/target/classes` — meaning the Maven build silently skips them entirely. This differs from the per-method dead-scaffolding pattern seen in OTIMS/DietAndKitchen/Pharmacy (a stray commented-out `addSample`/CRUD template method inside an otherwise-live controller); here the *entire* controller layer of this module is inert. Their 4 catch blocks (3 + 1) are excluded from the findings count for the same reason those per-method dead catches were excluded in prior audits — they cannot execute.
- **The one live file's only method is itself unreferenced anywhere in the compiled codebase — a second, distinct dead-code finding.** `HisService.publish()` is called from exactly one place in the entire repository: `RabbitMQController.publishHis()` — which is inside the dead/commented-out file above. A repo-wide grep for `HisService` outside `legacy/RabbitMQ` returns zero hits, and `legacy/Global` (which has its own `EmrService`/`OtimsService`/`ConsumerService` under the same `com.param.rabbitmq.service.*` package prefix — see next caveat) has no `HisService` package at all. So the one catch block this audit does report as a finding sits in code that compiles but that nothing in the live application actually invokes.
- **Billing-critical determination, 4-criterion walkthrough:** (a) package check — no file lives under `com/param/billing/` or `com/param/global/billing/`; all 4 files are under `com/param/rabbitmq/{controller,service/HisService}`. Zero hits. (b) filename/path keyword check (`payment|invoice|tariff|discount|deposit|fund|insurance|razorpay|pesapal|charge|voucher|refund|bill|consumption|collection|sanction|mpesa|ccavenue`) — zero matches, on filenames or file content (checked both). (c) reverse-import check — does `legacy/Billing` or `legacy/Global` import anything from *this module's own* packages (`com.param.rabbitmq.controller.*` or `com.param.rabbitmq.service.HisService.*`, the only packages that physically exist inside `legacy/RabbitMQ`)? Zero hits. (d) forward-import check — does any of the 4 files import `com.param.billing.*` or `com.param.global.billing.*` directly, or call into a billing service/DTO? Zero hits — `HisService.java` only imports `com.param.rabbitmq.dto.base.Request` and `com.param.rabbitmq.util.conn.RabbitMQ`. Result: 0 billing-critical files.
- **A package-name collision with `legacy/Global` is the key structural finding of this audit, and is the reason the task's own "check for billing/charge events" hint doesn't apply to this module's actual scope.** `com.param.rabbitmq.*` is not exclusive to the `legacy/RabbitMQ` Maven module — `legacy/Global/src/main/java/com/param/rabbitmq/` contains a separate, much larger, and *actually used* RabbitMQ integration: `service/EmrService/{EmrService,IEmrService}.java`, `service/OtimsService/{OtimsService,IOtimsService}.java`, `service/consumerService/{ConsumerService,IConsumerService}.java`, `dto/base/{Request,Response,Payload,Data}.java`, `util/conn/{RabbitMQ,RMQConnection}.java`, `util/constants/MasterKeyConstants.java`, and `dao/{ConsumerDao,IConsumerDao}.java`. This is precisely what the dead `RabbitMQController.java`/`RabbitMQConsumerController.java` in this module were trying to import (`EmrService`, `OtimsService`, `ConsumerService`) before being commented out — those classes simply don't exist inside `legacy/RabbitMQ` itself, only inside `legacy/Global`, which is almost certainly *why* those two controllers had to be commented out (they would not compile against this module's own source tree). Reverse-import search confirms 3 `legacy/Billing` files (`CardTypeMasterServiceImpl.java`, `VaccinationMasterServiceImpl.java`, `InsuranceMasterServiceImpl.java`) and 1 `legacy/Global` billing-package file (`com/param/global/billing/service/DoctorCategoryMasterServiceImpl.java`) import from that **Global-side** `com.param.rabbitmq.*` package — plus dozens more files across `legacy/Global`'s own master-data services (country/city/area/district/state, doctor, surgery, speciality, ambulance-tariff, referral, prefix, relation, gender, unit-application-billing-configuration, OTIMS operation-theatre masters, etc.). None of those imports resolve to anything inside the actual `legacy/RabbitMQ` module scanned in this audit. **Practical implication: the "HIS message relay could carry billing/charge events" hypothesis is true of the codebase overall, but the code that does it physically lives in `legacy/Global`, not in `legacy/RabbitMQ` — this module (as scoped) is a much smaller, largely orphaned remnant.** This is the same kind of shared-package-across-modules situation flagged in the OTIMS audit (`com.param.otims.model` living in `legacy/Entity` rather than `legacy/OTIMS`), just inverted: there, the module's own name was used by content living *outside* it; here, a materially different and much larger implementation *outside* this module reuses this module's package name.
- **This package-collision discovery does not change any classification in this audit** — it is out of scope (per this task's own framing, an audit of `legacy/RabbitMQ`'s 4 files only) but is flagged prominently for the owner, since it directly explains why this module — despite being an "HIS relay" that could very plausibly touch billing — shows 0 billing-critical findings, and because the real RabbitMQ-billing linkage (in `legacy/Global`) has almost certainly already been swept by the separate `legacy/Global` audit (`docs/AUDIT_Global_exceptions.md`) under its own package paths, not under a `com.param.rabbitmq.*` heading — worth a cross-check by the owner if a `com.param.rabbitmq.*`-specific finding count is ever needed from that audit.
- **`status-masks-failure`** (the `return null;`-only pattern from BR-003/BR-005) has **exactly 1 instance** — this module's only finding. For comparison across the series: Billing 3, Global 37, ADT 9, Pharmacy 4, BloodBank 0, CSSDMaster 0, DietAndKitchen 0, OTIMS 0. RabbitMQ is therefore only the fifth module in the series to show this pattern at all, and unusually, it is the *only* finding this module has (in every prior module with a nonzero count, `status-masks-failure` was a small minority of a much larger silent-swallow total).
- **Multi-catch clauses** (`catch (TypeA | TypeB e)`) — zero occurred in this module, same as every prior audit in this series.
- **Interface files:** 1 (`IHisService.java`), zero catch blocks by construction, not double-counted as "clean".
- **Scope has no `src/test/java` directory**, same as CSSDMaster, Pharmacy, DietAndKitchen, and OTIMS.
- This audit does **not** re-scan `legacy/Billing`, `legacy/Global`, `legacy/ADT`, `legacy/BloodBank`, `legacy/CSSDMaster`, `legacy/Pharmacy`, `legacy/DietAndKitchen`, `legacy/OTIMS`, `legacy/Entity`, or any other module — it is `legacy/RabbitMQ`-only, matching this task's scope. In particular, it does **not** audit the separate, much larger `com.param.rabbitmq.*` package tree that physically lives inside `legacy/Global/src/main/java/com/param/rabbitmq/` (see caveat above) — that code was in scope for, and is presumably already captured by, `docs/AUDIT_Global_exceptions.md`.
