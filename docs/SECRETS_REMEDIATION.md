## New findings surfaced during verification — NOT fixed in this batch (out of the named scope)

- **`legacy/LIS/src/main/java/com/param/lis/reports/service/SendReportToMail.java`** — hardcoded, the same SMTP password family fixed in ADT's `IMailConstants.java`, but a different module/file not named in item 11.
- The Global SMTP password family (the same one fixed in `Global/.../mail/IMailConstants.java`) also appears live in `Global/.../mail/MailingServiceImpl.java` and `Global/.../unit/service/SmsUtilityConfigServiceImpl.java`, and also appears (not necessarily as a secret — needs review) in two SQL/DDL artifacts: `legacy/Database/HIS-SME-DDL_20210430_150255584.sql`, `legacy/devops/HIS-SME-DDL_20210430_150255584.sql`, and `legacy/Deployment/HIS-DDL-20211019_124148463PM`. These are data/DDL files, not application code — touching them is a materially different, higher-risk kind of change than anything in this batch and needs its own explicit decision.
- **`legacy/Global/src/main/java/com/param/global/dao/PatientRegistrationDaoImpl.java~`** — a stray editor-backup file (note the trailing `~`), tracked in git since the very first baseline commit, containing the same `sa` credential fixed under item 7. Backup files like this shouldn't be tracked at all, but deleting it is a separate file not named in scope.

## Infrastructure discovery: `legacy/.gitignore` was itself never tracked

While adding the required ignore entry for the new `.local` files, discovered that `legacy/.gitignore` — despite clearly being in active use (it already had a rule ignoring `HIS-WAR/src/main/resources/jdbc.properties`) — has **never been committed to git** (it matches its own `*.gitignore` pattern and was apparently always a local, per-developer file). This meant the entire "keep local secrets out of git" convention this project already relied on for `jdbc.properties` was never actually enforced for anyone doing a fresh clone — only for whoever's local working copy happened to already have this file. **This batch force-adds `legacy/.gitignore` to git for the first time**, so the existing `jdbc.properties` rule and the new `devops/*.properties.local` rule are both finally real, versioned protections rather than tribal knowledge.

## DEPLOYMENT REQUIRED BEFORE THIS MERGES

Every one of these must be set on **every server/runner that builds or runs the affected code**, or the affected feature will fail (either a clear startup/connection error, or — for the properties-file cases — a broken config value):

- [ ] **Environment variables**, wherever the application actually runs (all environments — these are read at JVM runtime via `System.getenv`, not build time):
  - `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` (item 1 — profile picture / document upload to S3, ADT module)
  - `TWILIO_ACCOUNT_SID`, `TWILIO_API_KEY`, `TWILIO_API_SECRET`, `TWILIO_AUTH_TOKEN` (item 2 — video-call/chat features)
  - `BACKLOG_API_KEY` (item 3 — production-support ticket creation)
  - `PESAPAL_CONSUMER_KEY`, `PESAPAL_CONSUMER_SECRET` (item 4 — Pesapal payment integration)
  - `HIS_SUBSCRIPTIONS_DB_URL`, `HIS_SUBSCRIPTIONS_DB_USERNAME`, `HIS_SUBSCRIPTIONS_DB_PASSWORD` (item 8 — organization-lookup-by-name feature, Global module)
  - `SMARTLINK_DB_URL`, `SMARTLINK_DB_USERNAME`, `SMARTLINK_DB_PASSWORD` (item 9 — smart-card exchange-file lookup, Billing module)
- [ ] **Local files on each of the 7 live preprod deploy runners** (item 5) — `legacy/devops/jdbc.<env>preprod.properties.local` must exist with real values before that environment's deploy script runs, for: `meditestpreprod`, `mrrchpreprod`, `nchpreprod`, `queenspreprod`, `bpppreprod`, `oysterpreprod`, `athaayupreprod`.
- [ ] **Razorpay/SMTP secrets are not wired for 5 environments — MERGE BLOCKED on this until resolved.** While investigating item 6, found that `smepreprod`, `smetwo`, `smetwopreprod`, `smeone`, and `his-qa` have no active mechanism to supply `razorpay.key.id`/`razorpay.secret.id`/`axios.mailPassword` other than whatever was already sitting in the (now-scrubbed, and for the sed-based environments, apparently never-git-tracked) `jdbc.properties` file on that runner.
