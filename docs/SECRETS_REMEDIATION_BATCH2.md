## Scope note: `IMailConstants.java` interfaces intentionally left untouched

Both `ADT/.../common/IMailConstants.java` and `Global/.../mail/IMailConstants.java` still contain their own copies of these same SMTP password literals in `master` today. That's expected and out of scope here: Batch 1 already investigated and deleted both interfaces' `SMTP_USER_PWD` fields (they're fully unreferenced dead code) on the `fix/batch1-secrets-remediation` branch, which has not yet merged to `master`. This batch's branch is based on `master`, not on Batch 1's branch, and none of this batch's 5 items touch those two interface files — so there is no double-fix or conflict, just two independent branches each owning a disjoint set of files, to be reconciled at merge time (Batch 1's branch removes the dead interface fields; this batch's branch fixes the *live* code that happened to hardcode the same literal values directly instead of importing them from those interfaces).
