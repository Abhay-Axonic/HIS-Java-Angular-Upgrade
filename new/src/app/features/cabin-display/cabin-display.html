AMBER — known defect, permanent warning: the Cabin Display token feed (POST /api/opd/token/getDoctorTokenList) is broken by a phantom column: the named query GET_DOCTOR_TOKEN_LIST selects em.doctor_latest_call, which does not exist in opd.t_encounter_master. Every call throws at query execution and the DAO catch swallows it into a masked 501 "Something went wrong!!" envelope — the response it would read is the thing that lies: a "failed" body with no detail instead of the token row set. The sibling latest_call phantom on the same table (Counter Worklist's search feed, screen 49) confirms this is a family: the table lost columns that named queries still reference.

Why this warning is permanent: the phantom column is referenced in the entity's named query (EncounterMaster.java:1176) but absent from the live schema (verified against information_schema; all 7 joined tables exist and every other column resolves). A fix requires either adding the column (a schema change, Expand-Migrate-Contract territory) or rewriting the query — both out of scope for a parity rebuild, so the defect is surfaced here rather than hidden.
