AMBER — known defect, permanent warning: the Counter Worklist search feed (POST /api/opd/getSearchedListEncounterMaster) is broken by phantom columns: the named query GET_SEARCH_ENCOUNTERED_LIST selects enMst.latest_call and joins on enMst.nursing_station_id, but neither column exists in opd.t_encounter_master. Every call throws at query execution and the DAO catch swallows it into a masked error envelope (status "error" with a null code and null message) — the response it would read is the thing that lies: a 200 "error" body with no message instead of the row set.

Why this warning is permanent: the phantom columns are referenced in the entity's named query but absent from the live schema (verified against information_schema; all 28 joined tables exist). A fix requires either adding the columns (a schema change, Expand-Migrate-Contract territory) or rewriting the query — both out of scope for a parity rebuild, so the defect is surfaced here rather than hidden.
