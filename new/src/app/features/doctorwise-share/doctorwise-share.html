AMBER — known defect, permanent warning: the doctor-share save lies about a failed voucher write

saveDoctorShareList returns body status SUCCESS with an ERROR_MESSAGE when the voucher write fails — after the share rows were already updated. The UI shows success for a failed write on a money path.

TDoctorShareDaoImpl.saveDoctorShareList (lines 680-726): the share-row executeUpdate loop runs first (684-701); the voucher save (708) can return non-SUCCESS or a null object — line 724 then returns SUCCESS + ERROR_MESSAGE anyway. The share amounts changed, the voucher was not written, and the caller (which checks status == "success") shows success. Line 726: the empty-list path returns SUCCESS "saved" with nothing written.

Not fixed (Rule 10 — backend BR candidate; the BR-188 family).

Why this warning is permanent: the save path reports success without writing — you have not hit it, and this warning cannot be shown at save time because the response it would read is the thing that lies.
